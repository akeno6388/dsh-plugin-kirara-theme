# 已知限制与取舍

| 限制 | 影响 | 为什么接受 |
| --- | --- | --- |
| 选择器按 CSS Modules 的本地名后缀匹配，仍要求宿主保留这几个容器 | 宿主改掉列 / 外框 / 侧栏面板根的结构或本地名后，对应那层不再半透明、圆角消失 | 只依赖本地名（跨构建、跨宿主版本稳定），不唯一的后缀都配了结构 / 属性锚点；降级后果仅是「该处不透明 / 圆角消失」，布局不坏 |
| 磨砂只由「列」承担，内层实色一律被清成 `transparent` | 宿主以后新增的、以不透明 `bg-base` 铺满主区的面板仍会是纯色面板 | 侧栏 / 右侧栏内已按「列内全部 `_root`」统一清掉；中心列只清会话根，因为列内其余 `_root` 是代码块、turn 卡片这类**本来就该有底**的卡片 |
| 侧栏只补了右上角圆角 | 侧栏的左侧两角仍是直角（与窗口边缘平齐） | 视觉上只需与内容卡左上角圆角呼应；其余三角贴窗口边，圆角反而会出现不合缝的空隙 |
| `:root[data-windows-titlebar]` 选择器 | 普通浏览器页面里不生效（圆角与顶栏透明都不生效） | 该属性由桌面壳设置；浏览器里本来也没有原生拖拽条，此时顶栏那条根本不存在 |
| 顶栏透明靠「清具体元素」而非改 token | DSH 若换掉顶栏那两层（改类名或改由别的元素铺底），顶栏会又出现一条比照片更亮的横带 | 改 `--dsw-specific-sidebar-fill` 会连带把菜单与浮层一起变透明；症状可自检，降级不破坏布局 |
| 顶栏透明后，顶栏上的固定控件（侧栏折叠 / 新建会话）直接压在照片上 | 对比度只由 `.55` 黑遮罩兜底 | 与 Kirara 首页语义一致；控件自身有主题色底板，实测可辨 |
| 标题栏透明依赖宿主接受**带 alpha** 的 overlay 色 | 若某个宿主版本把带 alpha 的值当无效值、只取 RGB，带子会退回该颜色的 RGB 分量（浅色主题白、深色主题黑） | 这是刻意留的兜底：值写成 `rgba(255,255,255,0.004)` / `rgba(0,0,0,0)`（浅色用 1/255 是因为宿主的 canvas 往返会把 alpha=0 的 RGB 抹成 0），RGB 分量就是想要的实色；页面侧无法探测宿主行为，只能这样保底。本宿主 Electron 44 实测正常透明 |
| 标题栏透明依赖 preload 探针仍在页面里 | 若 DSH 以后不再建那个探针 span（或改了它的行内 style 文本），规则匹配不到 ⇒ 标题栏保持宿主自己推的颜色 | 匹配用的是 `span[style*="--dsw-specific-sidebar-fill"]`（探针唯一特征），失败只是「维持原样」，不报错 |
| 探针规则的**发射顺序**必须与宿主 `bootCss()` 逐行一致 | 顺序不同 ⇒ `check-css-parity` 失败（部署自检第 6 项） | 这是反漂移契约的一部分；改规则位置时两个文件要一起改 |
| 首次登记仍需完全重启一次 DSH | 第一次装完不能立刻看到外观 | `dsh.profile.bundles` 只在启动时读一次，属于宿主侧约束；登记过之后，插件列表里的开关就是即时的（不重启、不刷新） |
| 顶栏去掉遮罩后，窗口按钮图标的对比度只由 `.55` 黑遮罩承担 | 极亮背景图上按钮图标可能偏淡 | 与 GUI 其余部分同一层遮罩，视觉一致优先 |
| 首屏注入的 CSS 拿不到「尚未读盘完成」的图 | 极冷的首帧是渐变，随后换成图片 | `restoreFromDisk()` 还在 await 时 `bootCss()` 已同步执行；客户端挂载时立刻探一次 `state.json`，没图还会以 1.5s 暖机重试，不干等 10s |
| 宿主首屏样式靠**文本标记**认领才能回收 | 若宿主把 `kind:"style"` 行的渲染形式换掉（例如自己包一层带属性的元素），或有人只改了一边的 `BOOT_MARKER`，关插件后外观会留到刷新页面 —— 且**不报任何错** | `kind:"style"` 渲染出来是裸 `<style>…</style>`，没有任何属性可挂；标记拼在 `bootCss()` 之外，CSS 同源契约不受影响，部署自检第 7 项专门盯这条 |
| 客户端挂载后 30s 内「还没图」就每 1.5s 探一次 `state.json` | 服务器始终没有图时，这 30s 里多出约 20 次本机同源请求 | 只发生在「还没拿到图」的暖机窗口，拿到图或超时即回到 10s / 180s 常态；换来的是「打开开关后照片立刻出现」 |
| 缓存目录默认位置靠探测 | 未设 `DSH_HOME` 时落到 `~/.dsh/kirara-theme` | DSH 没有 `plugin-data` 约定，只能逐级兜底 |
| `?v=<version>` 与 `immutable` 头并用 | 略微冗余 | 版本化 URL 语义更清晰，且保证版本切换时 URL 唯一 |
| `/kirara-theme/*` 无需鉴权即可读 | 同源本机资源对外可读 | 它是**同源本机**资源路由，且背景图本身就是公开资源；但**绝不**用它代理任何敏感内容 |
| 输入区底座的渐变被去掉 | 滚到输入框下方的正文不再被 36px 实色带遮住，会一直透到照片上 | 主界面从顶到底同一种透明度，视觉更一致；可读性由 `.55` 黑遮罩兜底 |
| 侧栏底部渐隐被去掉 | 会话列表滚到底时文字直接压在照片上 | 那截实色终点属于「不透明侧栏」时代，与整块半透明面板不再一致 |
| 换图没有淡入过渡 | 换图是瞬时的 | 自定义属性的取值是离散的，不能 transition；改成淡入需要额外一层节点，与「不插 DOM 节点」的设计冲突 |
